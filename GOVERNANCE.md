# Governance

This project is maintained with a pragmatic and transparent governance model focused on stability, quality, and community collaboration.

## Project Roles

- Maintainer: Responsible for roadmap direction, release decisions, and final merge authority.
- Contributors: Anyone who opens issues, discussions, pull requests, documentation updates, or test improvements.
- Reviewers: Contributors or maintainers who review and validate pull requests.

## Decision Making

1. Small changes are handled through pull requests and normal review.
2. Medium changes should be proposed in Discussions before implementation.
3. Major architecture or workflow changes should include:
   - problem statement
   - options considered
   - tradeoffs
   - migration or rollback notes

Final decisions are made by maintainers after considering community feedback.

## Pull Request Policy

- At least one review is required before merge.
- CI must pass before merge.
- Security-sensitive changes require maintainer review.

## Release Process

- Releases are versioned and published through GitHub Releases.
- Changelog updates should accompany release-ready pull requests.
- Emergency security patches may be released outside normal cadence.

## Code of Conduct and Enforcement

Community behavior is governed by [.github/CODE_OF_CONDUCT.md](.github/CODE_OF_CONDUCT.md).

Conduct reports and moderation decisions are handled by maintainers.

## Governance Updates

Governance can evolve. Proposed changes should be opened as a pull request and discussed publicly.
